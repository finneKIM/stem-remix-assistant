# 실험 규칙

이 프로젝트는 앞으로 여러 생성 모델과 조건화 방식을 계속 시도할 가능성이 높아, 실험 단위로 구조를 통제한다.

## 실험 단위

브랜치와 폴더는 모델 이름이 아니라 **실험 단위**로 나눈다. 같은 모델을 다른 조건으로 다시 시도해도 새 실험 번호를 받는다.

```
experiments/
  exp_001_baseline/       # MusicGen 단독 생성 + Demucs 단독 분리 (01번 노트북)
  exp_002_musicongen/     # 재생성 파이프라인 A — MusiConGen
  exp_003_melody_style/   # 재생성 파이프라인 B — MusicGen-Melody/Style
```

각 실험 폴더는 다음을 포함한다.

- `config.yaml` — 모델, 프롬프트, 입력 조건 등 재현에 필요한 설정
- `README.md` — 목적, 방법, 결과, 결론

## 브랜치 규칙

```
main
├── experiment/001-baseline
├── experiment/002-musicongen
└── experiment/003-melody-style
```

실험 결과가 좋으면 main에 merge하고, 결과가 낮아도 브랜치는 삭제하지 않고 그대로 보존한다. 실패한 실험도 왜 실패했는지가 기록의 일부다.

## 지금은 하지 않는 것

`result.json` 표준 스키마, 실험 결과 자동 비교/시각화 스크립트, 정형화된 청취 평가 루브릭은 실험이 3개 이상 쌓여 손으로 비교하기 번거로워질 때 추가한다. 지금은 실험이 2~3개뿐이라 과도한 자동화보다 `README.md`에 결과를 직접 정리하는 쪽이 더 빠르고 정확하다.
