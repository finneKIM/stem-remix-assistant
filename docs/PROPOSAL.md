# 스템 리믹스 도우미 (Stem Remix Assistant) — 프로젝트 기획서

> 원하는 분위기의 음악을 생성하고, 스템 단위로 분리한 뒤, 마음에 들지 않는 파트만 재생성해 교체하는 반복적 음악 창작 도구
>
> 작성자: 김하나 | 최종 수정: 2026-08-13 | 상태: 기획 단계

---

## 0. 요약

텍스트 프롬프트로 음악을 생성하고(MusicGen), 스템 단위로 분리한 뒤(Demucs), 마음에 들지 않는 파트만 다시 생성해 교체하는 생성-분리-재생성 루프를 예산 0원으로 구현하는 프로젝트. 스템 단위 조건부 재생성이라는 이상적인 방식은 아직 오픈소스로 공개되어 있지 않다는 것을 확인, 현실적인 우회 파이프라인을 설계하고 검증하는 과정 자체를 이 프로젝트의 핵심 산출물로 둔다.

---

## 1. 배경

음악을 만들고 싶은 사람은 많지만, 결과물이 마음에 들지 않을 때 "이 부분만 다시" 라는 니즈를 해소해주는 도구는 드물다. 대부분의 AI 음악 생성 서비스는 전체 곡을 통째로 재생성하는 구조라, 마음에 드는 80퍼센트를 버리고 처음부터 다시 뽑아야 하는 비효율이 생긴다. 생성물을 부분적으로 통제하며 반복 개선하는 경험을 값싸게 제공하는 것이 장기적인 관심사이며, 이 프로젝트는 그 첫 단계다.

제약 조건은 다음과 같다.

- 예산 0원, 오픈소스 및 무료 도구로만 구성
- 사용 가능한 GPU는 Google Colab 무료 티어(T4) 수준

---

## 2. 사전 조사 및 기술적 한계 검증

기획 단계에서 실제로 조사하고 검증한 내용을 정리한다. 이상적으로 하고 싶었던 방식과 실제로 가능한 방식 사이의 간극을 그대로 남긴다.

### 2.1 이상적인 방식: 스템 조건부 생성 (Stem-conditioned Generation)

원래 목표는 드럼과 베이스는 그대로 두고 특정 파트만 다시 만들어달라고 요청하면, 나머지와 자연스럽게 어우러지는 새 스템을 생성해주는 모델을 쓰는 것이었다. 이런 능력을 가진 연구가 실제로 존재한다.

| 연구 | 발표 시점 | 상태 |
|---|---|---|
| MusicGen-Stem (Rouard et al.) | 2025.01 (arXiv 2501.01757), IEEE 게재 확정 | 논문에 코드와 가중치 공개 예정이라 명시했으나, 2026.08 기준 GitHub 저장소 확인 불가, 실질적으로 미공개 상태로 판단 |
| Stemphonic | 2026.02 (arXiv 2602.09891), ICASSP 2026 게재 예정 | 데모 웹사이트만 존재, 코드 및 모델 공개 여부 확인 불가 |

이 방식은 학계 최전선 연구 수준이며, 예산 0원으로 지금 당장 가져다 쓸 수 없다는 결론에 도달했다. 공개를 기다리는 대신, 이번 프로젝트에서는 우회 파이프라인을 직접 설계한다.

### 2.2 실제로 사용 가능한 도구 (검증 완료)

| 도구 | 역할 | 라이선스 및 비용 | 확인된 사실 |
|---|---|---|---|
| MusicGen (Meta, AudioCraft) | 텍스트 → 음악 생성 | 코드 MIT, 가중치 CC-BY-NC 4.0 (비상업 한정) | Colab 무료 T4에서 musicgen-stereo-medium으로 60초 생성 실사용 사례 확인 |
| Demucs (Meta) | 음원 → 스템 분리 | 오픈소스, 사전학습 가중치 즉시 사용 가능 | 학습 없이 바로 추론에 사용 가능, 경량이라 무료 GPU에서도 무리 없음 |
| OnAir Music Dataset | 검증 및 데모용 소규모 데이터 | CC BY-SA 4.0, 상업적 이용 포함 자유 사용 | 16곡, 스템 4종(드럼, 베이스, 보컬, 기타) 포함 |
| MUSDB18 | 정량 평가용 벤치마크 데이터 | CC BY-NC-SA (비상업), Zenodo 승인제 | 4.4GB(표준), 22.7GB(HQ), 신청 후 통상 1일 내 승인 |

### 2.3 채택하는 우회 파이프라인과 그 한계

방법: MusicGen으로 전체 트랙을 생성한 뒤 Demucs로 스템을 분리한다. 특정 파트가 마음에 들지 않으면, MusicGen의 melody conditioning으로 원곡의 멜로디와 코드 진행을 유지한 채 수정된 프롬프트로 트랙을 재생성한다. 새 트랙에서 원하는 스템만 추출해 원곡의 나머지 스템과 재조합한다.

이 방법의 알려진 한계는 다음과 같다.

1. 두 번의 생성 결과가 템포, 키, 타이밍에서 정확히 일치한다는 보장이 없다. melody conditioning이 어느 정도 완화하지만 완전한 싱크를 보장하지는 않는다.
2. 자연스러운 블렌딩이 이상적인 방식만큼 매끄럽지 않을 가능성이 높고, 이는 진행 중 정량적으로 측정해야 할 부분이다(4.3절 평가 지표 참고).
3. MusicGen 가중치가 CC-BY-NC이므로 이 파이프라인은 비상업적 용도로 한정된다.

이 한계는 감추지 않고 문서에 그대로 남긴다. 완벽한 결과보다 한계를 인지하고 우회하거나 측정한 과정을 보여주는 쪽을 택한다.

## 3. 목표

### 3.1 이번 단계의 목표

- 생성, 분리, 재생성, 재조합으로 이어지는 전체 파이프라인이 예산 0원, 무료 GPU 환경에서 end-to-end로 동작함을 증명
- 재조합 결과의 자연스러움을 주관적 인상이 아닌 최소한의 정량 지표로 측정
- Claude Code로 파이프라인을 설계, 구현, 디버깅하며 그 과정을 기록

### 3.2 이번 단계에서 다루지 않는 것

- 실시간 처리, 웹 서비스화, 배포는 다루지 않는다. 로컬 및 Colab 노트북 수준의 파이프라인으로 한정한다.
- 스템 조건부 생성 모델을 직접 학습시키지 않는다. 데이터와 컴퓨팅 자원상 비현실적이며, 기존 오픈소스 조합으로 근사한다.
- 상업적 이용은 고려하지 않는다. MusicGen 가중치 라이선스 제약에 따른다.

## 4. 시스템 설계

### 4.1 전체 흐름

```
[1] 사용자 프롬프트 입력
      ↓
[2] MusicGen으로 초안 트랙 생성 (예: "lofi hiphop with mellow piano, 90 BPM")
      ↓
[3] Demucs로 4-스템 분리 (드럼 / 베이스 / 보컬 / 기타)
      ↓
[4] 사용자가 마음에 들지 않는 스템을 지정 (예: 드럼이 마음에 안 듦)
      ↓
[5] 원곡의 멜로디와 코드를 melody conditioning으로 유지한 채,
    수정된 프롬프트로 MusicGen 재생성 (예: "punchier trap-style drums, same tempo")
      ↓
[6] 재생성 트랙도 Demucs로 스템 분리
      ↓
[7] 원하는 스템(드럼)만 추출해 원곡의 나머지 스템(베이스/보컬/기타)과 재조합
      ↓
[8] 정량 지표 측정 및 청취 비교로 결과물 산출
```

### 4.2 기술 스택

- 생성: MusicGen (facebook/musicgen-stereo-medium), AudioCraft 라이브러리
- 분리: Demucs (사전학습 htdemucs 모델)
- 실행 환경: Google Colab 무료 티어 (T4 GPU)
- 개발 도구: Claude Code
- 데이터: OnAir Music Dataset(검증용), 필요시 MUSDB18(정량 평가용, 승인 후)

### 4.3 평가 방법 (정량 지표 초안, 추후 구체화)

이상적인 스템 조건부 생성과 비교할 정답 데이터가 없어 완전한 정답 비교는 불가능하다. 대신 다음을 측정한다.

- 템포 및 비트 정합성: 원곡과 재생성 스템의 비트 타이밍 오차 (librosa beat tracking으로 측정)
- 키 및 코드 일치도: chroma feature 유사도
- 분리 품질: Demucs 분리 결과의 자체 지표(SDR 등, 가능한 범위 내에서)
- 주관 평가: 소수 인원 대상 A/B 블라인드 청취 테스트, 이질감 여부를 5점 척도로 수집
